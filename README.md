# LCM 上下文与历史 · v0.3.0

为 AstrBot 保存完整聊天与工具执行记录，并在后台把较老内容逐级压缩成历史摘要。提供当前上下文、完整历史和实际模型请求三个查看入口，摘要可以逐层展开到原始完整轮次。

适配 AstrBot **4.29.1**，声明兼容范围为 `>=4.29.1,<4.30.0`。交付为独立插件，通过事件钩子和可撤销的工具循环接入运行；插件包包含页面，无需另建网页服务。源码与版本包通过 [GitHub 仓库](https://github.com/littleApricot/astrbot_plugin_lcm) 分发，更新沿用现有共享插件源。

## 安装与开始使用

1. 刷新下面的共享插件源，搜索“LCM 上下文与历史”安装；也可在插件管理中用仓库地址安装，或从 [v0.3.0 发布页](https://github.com/littleApricot/astrbot_plugin_lcm/releases/tag/v0.3.0) 下载 ZIP 后使用文件安装。
2. 打开插件配置。首次使用可保留 `base_tokens=40000`；`summary_provider_id` 留空时，后台摘要使用该会话当前的回复模型。API Key 沿用 AstrBot 已配置提供商，无需在本插件另填。
3. 确认 AstrBot 提供商的模型上下文窗口设置正确。含图片的历史需要摘要模型支持视觉；也可以为摘要单独指定已配置的视觉提供商。
4. 收到新消息后，打开 AstrBot 侧栏中本插件的 `context` 页面。原生页面入口可能位于插件名称下；页面内标题为“上下文与历史”。

共享插件源与之前的回复判断、表情图库和自维护提示词插件相同；已经添加过时，直接刷新原源即可：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

仓库地址为 `https://github.com/littleApricot/astrbot_plugin_lcm`。后续版本更新元数据、Git 标签、Release 和共享源条目及其 MD5；安装与一键更新读取源中固定版本标签的 ZIP，运行数据继续留在插件数据目录。

启用后，进入消息事件钩子的用户消息会在回复判断之前入库，未回复的群消息也保存。现有回复判断插件继续负责 @ 和普通消息的回复策略：@ 绕过判断；普通消息只裁剪判定副本，正式回复使用 LCM 历史。

首次遇到一个会话时，会导入该会话仍保留的模型历史。**启用前独立存储的群消息、其他旧会话的批量迁移尚未实现**；这些旧数据继续留在 AstrBot 原库，不能把页面视为已覆盖全部旧聊天。旧记录无法补造真实时间、发送者和当时的人格或请求快照，会明确标记未知或推断状态。

升级、重载或关闭插件宜在没有回复执行时进行；活跃回复中的热重载尚未验证。重新启动后，上次未结束的轮次标记为中断，压缩任务恢复重试。

## 跟随有效历史

原始档案用于查证，当前有效历史用于后续回复、token 估算和后台压缩。默认保留完整工具过程；其他插件通过 AstrBot 的 `conversation_manager.update_conversation(..., history=...)` 修改历史后，LCM 自动跟随成功保存的结果。以后新增工具沿用这个共同入口即可，无需在 LCM 中登记工具名。

例如表情工具当前轮完成搜索和选图，再将持久历史改为“发出的图片 + 最终文字”，下一轮和后续摘要就只使用这份有效内容。完整搜索、调用参数和工具结果仍在原始档案中，可通过历史页面或检索工具查回。直接向平台发图的工具仍需把图片写入正常会话历史，LCM 才能将其作为模型可见的历史图片。

原生保存器的消息级 `_no_save`、临时内容片段和检查点按其保存语义处理；不完整的工具调用与结果配对会从有效历史中一起清理。只临时改某轮请求、但未保存历史的内容，不会成为持久历史修改。

修改已经压缩的内容，会使受影响的摘要及其上层摘要失效，恢复其余仍有效的来源，再按原规则后台压缩。原始档案和旧摘要保留，页面将有效替换记录标为“历史修订”，可展开查看来源。修改仅作用于已映射到原生历史的记录；从未进入该历史的未回复群消息继续保存和参与上下文。

每次模型调用前读取最新有效历史，包括工具后的下一次调用；已发出的调用保留发出时的输入。本轮用户输入和未结束的工具过程单独保留。历史写入使用短锁，并行生成继续独立进行；旧轮次结束时会保留期间其他回复及历史修改。原生保存失败时不发布该轮输出；若原生已保存而 LCM 同步中断，会在后续请求前核对数据库并补偿。旧版本升级时首次建立对应关系，无法凭空恢复启用前已丢失的历史。原生消息没有稳定 ID，完全同文的重复记录仅能按顺序和本轮来源匹配。

## 压缩与完整轮次

- 原文是 L0，原文摘要是 L1，L1 的摘要是 L2，依次递推。
- 每层自身达到约 `2B` 时，后台选择较老约 `B` 的完整内容压缩。默认 B 为 **40,000 估算 tokens**，因此通常在本层约 80,000 时触发。
- 一轮的原始档案包括本次新增输入、所有模型调用、完整工具参数与结果、最终回复。压缩使用该轮的有效内容；边界落在轮次内部时，整轮留在较新一侧，已结束的超大旧轮次可整体处理，保留区允许超过 B。
- 摘要没有额外的固定字数或输出长度目标。按实际生成内容重新估算占用；空摘要、占用等于或超过来源的结果、截断或缺乏正常结束标志的结果均不发布。
- 压缩只替换后续上下文中的表示。原文、下层摘要和来源关系持续保存；原始工具结果保持全文，页面折叠只影响显示。

例如原文共 82K，旧的完整轮次共 35K，下一轮跨过 40K 分界，则压缩 35K、保留 47K。上层按摘要自身的占用累计，原文的 35K 不会直接当作 L1 的大小。

后台固定来源，成功后只替换该批来源；任务期间新增的消息和并行回复继续追加。后续判断和每次正式模型调用使用最新已发布历史，本轮私有输入和工具过程接在该历史之后。LCM 不添加跨整个生成过程的会话锁。后台摘要当前全局并发为 1，但共用提供商时仍可能竞争配额和推理资源。

摘要提示词要求保留事实、话题、约定、纠正、称呼与未解决事项，并将历史语气作为资料。人格和长期记忆继续由现有插件管理，LCM 的有效历史修改不回写记忆队列。摘要、页面浏览和历史展开不会作为新群消息或最终回复加入记忆整理队列；检索工具执行默认正常进入当轮历史。

## 查看与搜索

| 入口 | 内容 |
| --- | --- |
| 当前上下文 | 最新已发布的历史基底、各层估算占用、版本和后台任务状态；该数字不包含下一轮尚未注入的人格、记忆和工具定义。 |
| 完整历史 | 原始用户消息、模型输出、完整工具执行及另存的历史修订；按新到旧分页。点击记录可以查看所属完整轮次或修订来源。 |
| 实际请求 | 选择轮次与模型调用步骤，查看实际交给提供商适配器的逻辑输入，包括当时的人格、记忆、工具定义及本轮已有执行内容。它不代表适配器最终序列化后的 HTTP 报文。 |

点击摘要的“逐层查看来源”，可以从高层摘要进入下层摘要，再看原始完整轮次；面包屑支持返回。用户展开来源仅影响页面阅读。模型调用历史工具取得的原文会作为正常工具结果进入当前执行。

搜索支持字面关键词、发送者、日期、原文或摘要、摘要层级。当前上下文内搜索只搜索可见文字，摘要背后的原文应切换完整历史搜索；实际请求内搜索只筛选所选快照的消息。检索按 Unicode 不区分大小写匹配，`%`、`_` 也按普通字符处理。

显示和日期筛选采用该会话的机器人时区，东八区显示 `GMT+8`；给模型的新历史消息带 `+08:00`。页面使用显式刷新和分页，阅读时不会被后台强制跳转。当前版本没有自动新版本提醒或相邻记录定位按钮。

消息中的图片、语音、视频和文件保留组件引用，并尽快后台保存可取得的文件；已归档图片可在页面查看。媒体缺失会显示状态。模型可从检索结果取得媒体 ID，再用 `lcm_expand` 返回归档图片供视觉模型查看；其他媒体返回路径和获取状态。

## 配置

所有 token 数均为估算，采用同一文本/结构与媒体开销计量规则，**不是提供商精确 tokenizer 或计费量**。切换模型后也使用该估算规则。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 启用 LCM；修改后重载插件。 |
| `base_tokens` | `40000` | 每层容量基准 B，正整数。原始档案不按 B 删除。 |
| `summary_provider_id` | 空 | 留空使用该会话当前回复提供商；非空使用指定的已配置提供商 ID。 |
| `summary_prompt` | 空 | 留空使用内置中性历史摘要提示词；修改只影响后续摘要。 |
| `max_input_tokens` | `0` | 0 按当前 AstrBot 模型的窗口减去最大输出配置自动计算输入预算；正数为额外输入上限，两者都存在时取较小值。 |
| `summary_timeout_seconds` | `180` | 单次后台摘要等待时间，最低按 10 秒执行。失败后退避重试，最长间隔一小时。 |

输出空间自动读取 AstrBot 该模型“自定义请求体参数”中的最大输出设置，按适配器支持的字段识别 `max_output_tokens`、`max_completion_tokens`、`max_tokens` 和 `maxOutputTokens`。正式回复、后备模型和单独指定的摘要模型各自读取自己的配置，每次调用重新计算。最大输出只需在 AstrBot 模型处维护。

没有配置有效正整数时，Anthropic 使用其适配器默认的 65,536，其余模型内部按 8,192 预留估算空间；该回退不修改提供商实际输出参数。最大输出必须小于已配置的模型窗口。

有限模型窗口仍是边界。估算输入超过有效预算会明确报错并保留原文，后台继续按规则整理；当前回复不会临时删历史或等待一次前台压缩。若提供商未设置窗口、插件输入预算也为 0，则以提供商自身限制为准。巨型完整轮次、过慢的摘要或持续失败，都可能使输入暂时超过可用窗口。

## 模型历史工具

三个工具只绑定当前群与当前 AstrBot 会话，模型不能自行指定其他群。管理页面可以切换已归档会话。LCM 请求中的内置 `get_group_message_history` 由下列工具替代。

| 工具 | 入参 | 结果 |
| --- | --- | --- |
| `lcm_search` | `query: string` 必填、非空；`target: raw/summaries/both` 默认 `both`；`sender: string` 可选；`start_time/end_time: string` 可选、带时区的 ISO 日期；`cursor: string` 默认首页；`limit: integer` 默认 20、范围 1–50。 | `ok`、完整命中记录 `records`、`next_cursor`。记录包含 ID、层级、时间、发送者、正文、轮次和可发现的媒体存档信息。 |
| `lcm_describe` | `id: string` 可选，空为当前目录；`cursor: string` 默认首页。 | `ok`、目录或 `node` 及直接子记录 `records`、`next_cursor`；每页默认 30 项。 |
| `lcm_expand` | `id: string` 必填，支持消息、轮次、摘要、媒体 ID；`target: children/original` 默认 `original`；`cursor: string` 默认首页；`limit: integer` 默认 1、范围 1–10。 | `ok`、直接子记录或完整原始单元 `units`、下一页游标；每单元包含完整轮次状态和 `records`。媒体 ID 返回 `media`；已归档图片以原生图片工具结果返回，其他媒体给出路径和状态。 |

普通结果以 JSON 文本返回；参数错误或跨会话访问返回 `ok=false,error`，空搜索返回空列表。搜索游标绑定范围与条件，不应挪到其他查询；其他分页游标应沿用同一节点与展开方式。完整轮次的页可以很大，超出请求预算时仍保留原始数据。

## 数据、停用与验证范围

数据位于 AstrBot 的 `data/plugin_data/astrbot_plugin_lcm/`：`history.sqlite3`、运行中的 WAL/SHM 文件及 `media/`。备份时停止机器人后复制整个目录，或使用 SQLite 的一致性备份方式并同时备份媒体。升级源码与删除数据是两件独立的操作；原始档案没有自动淘汰策略，文件和请求快照会持续增长。

停用后恢复 AstrBot 原有的上下文处理路径；LCM 档案仍在插件数据目录。原生会话的兼容历史可能已经包含摘要，停用不会自动把全部原文灌回原生模型历史。重新启用后仍可查询 LCM 档案。

发送成功钩子取得的实际发送链另存于 `deliveries`，当前页面主要展示模型执行记录；平台发送失败和绕过该钩子的工具直发，尚无完整发送状态追踪。旧数据的媒体批量补存与跨旧会话检索也尚未实现。

本版使用 AstrBot 4.29.1 的真实工具循环和确定性提供商做隔离验证，覆盖整轮边界、多级压缩、并行追加、后台发布、截断拒绝、重启恢复、历史检索、完整工具结果、记忆队列收集、回复判断副本及 @ 绕过。使用临时数据库与无头浏览器实测了页面逐层展开、搜索、请求查看、时区、明暗主题及窄屏布局。

有效历史同步另覆盖原生保存接口、历史改删、图片替换、临时内容过滤、摘要失效、过期压缩发布冲突及并行旧快照回写；测试使用临时数据库，不修改运行中的机器人。

尚未使用真实 QQ 或真实模型服务联调，摘要保真、真实模型的历史查回效果、费用与首字耗时均未验证。浏览器验证使用 AstrBot 原生页面服务和 SDK，父页面的认证请求由隔离宿主模拟；真实用户登录入口仍待安装后验证。

## 开发验证

使用已安装 AstrBot 4.29.1 依赖的 Python 环境：

```sh
PYTHONPATH=/path/to/AstrBot python -m pytest astrbot_plugin_lcm/tests -q
ruff check --isolated --select E4,E7,E9,F,I astrbot_plugin_lcm
node --check astrbot_plugin_lcm/pages/context/viewer.js
```

测试需安装 `pytest`、`pytest-asyncio`，不读取真实 API Key。部分兼容性测试会导入本项目旁边的 `astrbot_plugin_reply_gate`、`astrbot_plugin_self_prompt`，因此应使用完整工作目录。浏览器样例服务器还需 `uvicorn`，浏览器脚本需可用的 `playwright` 和 Chromium；可以通过 `CHROME_EXECUTABLE_PATH` 指向独立测试使用的 Chrome。

```sh
PYTHONPATH=/path/to/AstrBot python -m astrbot_plugin_lcm.tests.ui_server
# 在另一个终端执行：
cd astrbot_plugin_lcm
node tests/viewer.cjs
```

样例服务器仅监听 `127.0.0.1:6197`，使用临时目录，结束后可直接关闭。安装后的页面使用 AstrBot 原有页面服务，不运行这个样例服务器。
