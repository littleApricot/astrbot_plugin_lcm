# LCM 上下文与历史 · v0.6.4

为 AstrBot 保存完整聊天与工具执行记录，并在后台把较老内容逐级压缩成历史摘要。提供当前上下文、完整历史和实际模型请求三个查看入口，摘要可以逐层展开到原始完整轮次。

适配 AstrBot **4.29.1**，声明兼容范围为 `>=4.29.1,<4.30.0`。交付为独立插件，通过事件钩子和可撤销的工具循环接入运行；插件包包含页面，无需另建网页服务。源码与版本包通过 [GitHub 仓库](https://github.com/littleApricot/astrbot_plugin_lcm) 分发，更新沿用现有共享插件源。

## 安装与开始使用

1. 刷新下面的共享插件源，搜索“LCM 上下文与历史”安装；也可在插件管理中用仓库地址安装，或从 [v0.6.4 发布页](https://github.com/littleApricot/astrbot_plugin_lcm/releases/tag/v0.6.4) 下载 ZIP 后使用文件安装。
2. 打开插件配置。首次使用可保留 `base_tokens=40000`；`summary_provider_id` 留空时，后台摘要使用该会话当前的回复模型。API Key 沿用 AstrBot 已配置提供商，无需在本插件另填。
3. 确认 AstrBot 提供商的模型上下文窗口设置正确。正式回复按配置保留最近的历史图片；后台摘要使用图片的文字表示，可以采用文本模型。
4. 收到新消息后，打开 AstrBot 侧栏中本插件的 `context` 页面。原生页面入口可能位于插件名称下；页面内标题为“上下文与历史”。

共享插件源与之前的回复判断、表情图库和自维护提示词插件相同；已经添加过时，直接刷新原源即可：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

仓库地址为 `https://github.com/littleApricot/astrbot_plugin_lcm`。后续版本更新元数据、Git 标签、Release 和共享源条目及其 MD5；安装与一键更新读取源中固定版本标签的 ZIP，运行数据继续留在插件数据目录。

启用后，进入消息事件钩子的用户消息会在回复判断之前入库，未回复的群消息也保存。现有回复判断插件继续负责 @ 和普通消息的回复策略：@ 绕过判断；普通消息只裁剪判定副本，正式回复使用 LCM 历史。

首次遇到一个会话时，会导入该会话仍保留的模型历史。**启用前独立存储的群消息、其他旧会话的批量迁移尚未实现**；这些旧数据继续留在 AstrBot 原库，不能把页面视为已覆盖全部旧聊天。旧记录无法补造真实时间、发送者和当时的人格或请求快照，会明确标记未知或推断状态。

升级、重载或关闭插件宜在没有回复执行时进行；活跃回复中的热重载尚未验证。重新启动后，上次未结束的轮次标记为中断，压缩任务恢复重试。

## 提示分块与有效历史

配套更新记忆与记事本 **v0.5.1**、群聊表情图库 **v0.5.1**、自主语音回复 **v0.1.3** 和回复判断 **v0.8.3**。LCM 统一组装三类内容：

| 内容 | 提供方式 | 后续历史 |
| --- | --- | --- |
| 固定设定、性格和人设、回复偏好、昵称 | 系统提示，按来源插件分块 | 每轮重新提供 |
| 当前时间、记事本目录、图库新增与推荐 | 历史之后的本轮临时提示，按来源分块 | 只在当前请求中出现 |
| 已处理的用户、助手与工具消息 | 最新有效历史 | 回复、判断近期窗口及后台摘要共用 |

系统块标记为 `[系统提示｜来源：插件名]`，临时块标记为 `[本轮临时提示｜来源：插件名]`。尚未声明来源的现有系统内容归入 `astrbot.core/未声明来源`，避免误归给某个插件。实际请求快照额外保存 `context_sources`，供用户查看各块来源、字符数和历史声明；这些审计字段不提供给模型。

记忆插件的人格正文保留，面向用户的固定设定标题只在模型渲染中省略。图库命名与描述的生成规则交给识图模型，发送、修改、停用及 Wiki 原图路径规则放在实际工具描述中。主模型输入移除与沉默工具冲突的强制非空、过程汇报提示及不可用技能说明；群聊请求过滤 `oauth-status`、`oauth-logout`、`protect-page`，其余正常工具继续按原配置提供。

运行时临时块只显示当前时间，例如 `2026-10-25 03:11:20`。模型输入中已有的时间先换算到会话配置时区，再省略偏移和时区名称。助手历史直接提供回复正文，旧记录开头由 LCM 添加的 `[时间 机器人]` 标记在读取和后续保存时去除；用户消息的时间、正文里的日期和引用保留。消息发生时间继续保存在档案字段中，可由管理页或历史工具查询；原始档案保留，旧数据无需批量改写。

表情、语音及历史检索的用法随工具描述提供。图库推荐旁说明候选仅为部分图库、可以不用，也可继续搜索。回复判断只接收当前记忆、近期有效历史及当前时间，不接收本轮工具定义、目录或推荐；正常保存的历史工具调用与结果仍可参与判断。

原始档案用于查证，当前有效历史用于后续回复、token 估算和后台压缩。插件通过下述声明处理自己的历史；其他插件通过 AstrBot 的 `conversation_manager.update_conversation(..., history=...)` 成功修改历史后，LCM 同样跟随保存结果。

图库搜索和看图只留在当前执行过程，成功发图转成“机器人已发送图片”的历史附件；修改、停用结果及正常文字保留。后续回复、近期判断和摘要都使用这份表示。原参数、完整工具结果和图片引用仍保存在原始档案；压缩来源关系也包含被隐藏的原记录，避免剩下孤立工具结果。

原生保存器的消息级 `_no_save`、临时内容片段和检查点按其保存语义处理，原始档案另行保留；模型视图中留下的未完成工具过程按下文转换为文字资料。只临时改某轮请求、但未保存历史的内容，不会成为持久历史修改。

历史修订使用新 ID，并通过来源 ID 关联旧记录。模型取得当前记录 ID 后，用 `lcm_expand(id=当前记录ID, target="original")` 可沿多次修订查回最初原文；原始记录继续保留。同一批消息逐条修改时，等量替换按位置对应来源；合并或拆分仍保留该批来源。回复准备和判断后的刷新沿替换关系使用当前输入版本，并保留会话隔离、删除检查和其他轮次的占用检查。

修改已经压缩的内容，会使受影响的摘要及其上层摘要失效，恢复其余仍有效的来源，再按原规则后台压缩。原始档案和旧摘要保留，页面将有效替换记录标为“历史修订”，可展开查看来源。修改仅作用于已映射到原生历史的记录；从未进入该历史的未回复群消息继续保存和参与上下文。

每次模型调用前读取最新有效历史，包括工具后的下一次调用；已发出的调用保留发出时的输入。本轮用户输入和未结束的工具过程单独保留。历史写入使用短锁，并行生成继续独立进行；旧轮次结束时会保留期间其他回复及历史修改。原生保存失败时不发布该轮输出；若原生已保存而 LCM 同步中断，会在后续请求前核对数据库并补偿。旧版本升级时首次建立对应关系，无法凭空恢复启用前已丢失的历史。原生消息没有稳定 ID，完全同文的重复记录仅能按顺序和本轮来源匹配。

给模型拼接历史时，工具调用按 `tool_call_id` 与结果组成连续消息块；旧结果即使在较新的轮次中被修订，也仍紧跟原调用。不完整的执行、孤立结果和失败轮次中的工具过程以完整文字资料呈现，原参数、结果及 ID 保留在资料中。组装只改变请求副本，原始记录、修订来源与轮次归属继续保留。

历史保存使用同一份工具块投影对应回原消息 ID。已归档工具图片改用本地图片表示时，仍对应原记录，避免把图片表示的转换误判为内容修订。

## 图片窗口与原图查回

正式回复的历史图片支持两种保留模式，在“历史图片保留模式”中选择：

- `count`：按张数，默认保留最近 **5 张**，可用 `history_image_limit` 调整。同一条消息中的多张图片分别计数。
- `tokens`：按图片 token 估算预算，预算由 `history_image_token_budget` 设置，默认 **4096**。从最新历史图片向前累加，遇到放不下的图片后，更早图片全部转文字；不会跳过这张图再挑更老的小图。若最新图片本身超过预算，历史图片全部转文字。

两种模式互斥，默认采用 `count`，保留升级前设置；选择 `tokens` 后，张数设置不参与限制。任一模式的额度设为 0，都将历史图片全部转文字。更早图片使用表情图库中已有的名称和描述，未匹配时显示“图片”。匹配只读取已有资料，采用图库插件当前启用的配置；图库未启用、图片尚无描述或查询失败时同样显示“图片”。

历史修订沿来源关系继承媒体档案，继续使用原媒体 ID、本地图片副本和缺失状态。替换历史中的文字或时间显示后，已有本地副本仍可用于回复与原图查回。

已在媒体档案中标记为 `missing` 的历史图片也使用名称、描述或“图片”，保留消息与媒体 ID，不再把失效链接作为图片交给提供商。这类图片不占张数或图片 token 预算，额度用于其余可用的近期图片。原始链接和保存状态继续保留；这不能恢复归档失败且来源已失效的原图。尚未判定缺失的远程图片仍按原规则处理。

token 模式目前对 DeepSeek Flash 及其兼容旧名使用 [官方图片尺寸计算器](https://api-docs.deepseek.com/zh-cn/quick_start/token_usage/) 的 V4.1 规则。读取内嵌图片或本地图片的尺寸，并考虑 `detail=low`；远程链接不额外下载，尺寸不可取得时按官方单图上限 1024 估算。其他模型暂沿用 AstrBot 通用的每图 765 token 估算，尚未适配各厂商的视觉规则。模型别名后续切换版本时，也可能需要更新对应规则。

例如 DeepSeek Flash 下，256×256 或 512×512 正方形图片估算为 184 token，1024×1024 图片为 652 token。预算 836 可以保留最近一张小图和前面一张 1024×1024 图；预算 835 只能保留最近的小图。实际用量以服务商返回的 `usage` 为准。这个预算只统计保留历史图片的视觉 token，替代描述、聊天文字、人格和工具定义另算；图片上传字节数也由文件编码决定。实际请求快照保存 `history_image_window` 统计，记录模式、原有与保留张数、已知缺失张数，token 模式还记录预算、估算用量和采用的估算规则。

这个额度只限制历史部分。当前用户输入、同批尚待回复的消息，以及本轮工具搜索、看图或历史原图读取返回的图片均单独保留，不占用历史图片额度。每次模型调用重新投影最新历史，包括流式回复和工具后的下一次调用。

后台 LCM 整理把全部图片改用同样的文字表示；历史工具的文字结果也会把内嵌图片转成文字，保留消息与媒体标识及原文件路径。模型输入中的历史图片消息附有 `历史消息 id`，有媒体档案的消息还带 `媒体 id`。模型可以先用消息 id 调用 `lcm_expand` 取得媒体信息，再用媒体 id 调用 `lcm_expand` 查看已保存的原图。只有模糊的文字、发送者或时间线索时，可先调用 `lcm_search` 定位记录；摘要可通过 `lcm_describe` 查直接来源。

转换仅作用于发给模型的副本。原始图片、消息、有效历史和摘要来源继续保留；“当前上下文”页面展示的历史基底可以含有更多图片，“实际请求”展示本次投影后的提供商逻辑输入。已压缩的历史按摘要显示，原图仍须逐层查回。原图尚未归档或已经缺失时，工具会返回保存状态，不能保证所有旧消息都有本地原文件。

## 压缩与完整轮次

- 原文是 L0，原文摘要是 L1，L1 的摘要是 L2，依次递推。
- 每层自身达到约 `2B` 时，后台选择较老约 `B` 的完整内容压缩。默认 B 为 **40,000 估算 tokens**，因此通常在本层约 80,000 时触发。
- 一轮的原始档案包括本次新增输入、所有模型调用、完整工具参数与结果、最终回复。压缩使用该轮的有效内容；边界落在轮次内部时，整轮留在较新一侧，已结束的超大旧轮次可整体处理，保留区允许超过 B。
- 摘要没有额外的固定字数或输出长度目标。按实际生成内容重新估算占用；空摘要、占用等于或超过来源的结果、截断或缺乏正常结束标志的结果均不发布。
- 压缩只替换后续上下文中的表示。原文、下层摘要和来源关系持续保存；原始工具结果保持全文，页面折叠只影响显示。

例如原文共 82K，旧的完整轮次共 35K，下一轮跨过 40K 分界，则压缩 35K、保留 47K。上层按摘要自身的占用累计，原文的 35K 不会直接当作 L1 的大小。

后台固定来源，成功后只替换该批来源；任务期间新增的消息和并行回复继续追加。后续判断和每次正式模型调用使用最新已发布历史，本轮私有输入和工具过程接在该历史之后。LCM 不添加跨整个生成过程的会话锁。后台摘要当前全局并发为 1，但共用提供商时仍可能竞争配额和推理资源。

摘要直接整理经过声明处理的有效历史，不再按工具名或内容类别二次排除。保留事实、话题、约定、纠正、称呼、必要时间与未解决事项，归属影响理解时写进对应事实，不在开头列参与者名单；历史语气作为资料。人格和长期记忆继续由现有插件管理，LCM 的有效历史修改不回写记忆队列。摘要、页面浏览和历史展开不会作为新群消息或最终回复加入记忆整理队列；检索工具执行默认正常进入当轮历史。

## 查看与搜索

| 入口 | 内容 |
| --- | --- |
| 当前上下文 | 最新已发布的历史基底、各层估算占用、版本和后台任务状态；该数字不包含下一轮尚未注入的人格、记忆和工具定义。 |
| 完整历史 | 原始用户消息、模型输出、完整工具执行及另存的历史修订；按新到旧分页。点击记录可以查看所属完整轮次或修订来源。 |
| 实际请求 | 选择轮次与模型调用步骤，查看实际交给提供商适配器的逻辑输入，包括当时的人格、记忆、工具定义、本轮已有执行内容、临时提示及来源清单。它不代表适配器最终序列化后的 HTTP 报文。 |

点击摘要的“逐层查看来源”，可以从高层摘要进入下层摘要，再看原始完整轮次；面包屑支持返回。用户展开来源仅影响页面阅读。模型调用历史工具取得的原文会作为正常工具结果进入当前执行。

搜索支持字面关键词、发送者、日期、原文或摘要、摘要层级。当前上下文内搜索只搜索可见文字，摘要背后的原文应切换完整历史搜索；实际请求内搜索只筛选所选快照的消息。检索按 Unicode 不区分大小写匹配，`%`、`_` 也按普通字符处理。

显示和日期筛选采用该会话的机器人时区；模型输入使用不带时区后缀的本地时间。页面使用显式刷新和分页，阅读时不会被后台强制跳转。当前版本没有自动新版本提醒或相邻记录定位按钮。

消息中的图片、语音、视频和文件保留组件引用，并尽快后台保存可取得的文件；已归档图片可在页面查看。媒体缺失会显示状态。模型可从检索结果取得媒体 ID，再用 `lcm_expand` 返回归档图片供视觉模型查看；其他媒体返回路径和获取状态。

## 配置

分层容量、页面总体占用和总输入预算沿用通用的文本、结构与媒体开销估算。历史图片的 token 保留预算则按上文的模型相关规则单独计算，因此可能与页面总体占用中的通用图片估值不同。两者均为估算，**不是提供商精确 tokenizer 或计费量**。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 启用 LCM；修改后重载插件。 |
| `base_tokens` | `40000` | 每层容量基准 B，正整数。原始档案不按 B 删除。 |
| `history_image_mode` | `count` | 历史图片保留模式：`count` 按张数，`tokens` 按图片 token 估算预算。两者互斥。 |
| `history_image_limit` | `5` | `count` 模式下保留的最近历史图片数，按图片出现次数计数；0 将历史图片全部转文字，负数按 0 执行。 |
| `history_image_token_budget` | `4096` | `tokens` 模式下保留历史图片的视觉 token 估算预算；0 将历史图片全部转文字，负数按 0 执行。当前输入和本轮工具图片单独保留。 |
| `summary_provider_id` | 空 | 留空使用该会话当前回复提供商；非空使用指定的已配置提供商 ID。 |
| `summary_prompt` | 空 | 留空使用内置中性历史摘要提示词；修改只影响后续摘要。 |
| `max_input_tokens` | `0` | 0 按当前 AstrBot 模型的窗口减去最大输出配置自动计算输入预算；正数为额外输入上限，两者都存在时取较小值。 |
| `summary_timeout_seconds` | `180` | 单次后台摘要等待时间，最低按 10 秒执行。失败后退避重试，最长间隔一小时。 |

输出空间自动读取 AstrBot 该模型“自定义请求体参数”中的最大输出设置，按适配器支持的字段识别 `max_output_tokens`、`max_completion_tokens`、`max_tokens` 和 `maxOutputTokens`。正式回复、后备模型和单独指定的摘要模型各自读取自己的配置，每次调用重新计算。最大输出只需在 AstrBot 模型处维护。

没有配置有效正整数时，Anthropic 使用其适配器默认的 65,536，其余模型内部按 8,192 预留估算空间；该回退不修改提供商实际输出参数。最大输出必须小于已配置的模型窗口。

有限模型窗口仍是边界。估算输入超过有效预算会明确报错并保留原文，后台继续按规则整理；当前回复不会临时删历史或等待一次前台压缩。若提供商未设置窗口、插件输入预算也为 0，则以提供商自身限制为准。巨型完整轮次、过慢的摘要或持续失败，都可能使输入暂时超过可用窗口。

## 模型历史工具

三个工具只绑定当前群与当前 AstrBot 会话，模型不能自行指定其他群。管理页面可以切换已归档会话。LCM 请求中的内置 `get_group_message_history` 由下列工具替代。

启用 LCM 后，三个工具直接注册到 AstrBot 原生工具列表，收到第一条消息前即可查看。工具开关、人格工具选择和原生权限设置正常生效；人格若按名单选择工具，请将这三个工具一并勾选。需要调整模型看到的说明时，安装“工具说明编辑”v0.1.1 或更新版本，在其 `tools` 页面按 LCM 来源筛选并保存；参数名称、类型和必填规则沿用原定义。请求快照与输入预算使用修改后的工具定义。

调用时从当前消息事件读取已准备的 LCM 会话，不在全局工具对象中保存群聊范围。缺少有效会话、范围与当前群不符或插件已停用时，返回 `ok=false,error=lcm_context_unavailable`。

| 工具 | 入参 | 结果 |
| --- | --- | --- |
| `lcm_search` | `query: string` 必填、非空；`target: raw/summaries/both` 默认 `both`；`sender: string` 可选；`start_time/end_time: string` 可选，格式 `YYYY-MM-DD HH:mm:ss`，按会话配置时区解释；`cursor: string` 默认首页；`limit: integer` 默认 20、范围 1–50。 | `ok`、命中记录 `records`、`next_cursor`。记录包含 ID、层级、时间、发送者、正文、轮次及媒体 ID、原文件路径和状态；图片原始数据改为文字。 |
| `lcm_describe` | `id: string` 可选，空为当前目录；`cursor: string` 默认首页。 | `ok`、目录或 `node` 及直接子记录 `records`、`next_cursor`；每页默认 30 项。 |
| `lcm_expand` | `id: string` 必填，支持消息、轮次、摘要、媒体 ID；`target: children/original` 默认 `original`；`cursor: string` 默认首页；`limit: integer` 默认 1、范围 1–10。 | `ok`、直接子记录或完整原始单元 `units`、下一页游标；每单元包含完整轮次状态和 `records`，内嵌图片改为文字并保留媒体信息。媒体 ID 返回 `media`；已归档图片以原生图片工具结果返回，其他媒体给出路径和状态。 |

普通结果以 JSON 文本返回；参数错误或跨会话访问返回 `ok=false,error`，空搜索返回空列表。搜索游标绑定范围与条件，不应挪到其他查询；其他分页游标应沿用同一节点与展开方式。完整轮次的页可以很大，超出请求预算时仍保留原始数据。

## 数据、停用与验证范围

数据位于 AstrBot 的 `data/plugin_data/astrbot_plugin_lcm/`：`history.sqlite3`、运行中的 WAL/SHM 文件及 `media/`。备份时停止机器人后复制整个目录，或使用 SQLite 的一致性备份方式并同时备份媒体。升级源码与删除数据是两件独立的操作；原始档案没有自动淘汰策略，文件和请求快照会持续增长。

停用后恢复 AstrBot 原有的上下文处理路径；LCM 档案仍在插件数据目录。原生会话的兼容历史可能已经包含摘要，停用不会自动把全部原文灌回原生模型历史。重新启用后仍可查询 LCM 档案。

发送成功钩子取得的实际发送链另存于 `deliveries`，当前页面主要展示模型执行记录；平台发送失败和绕过该钩子的工具直发，尚无完整发送状态追踪。旧数据的媒体批量补存与跨旧会话检索也尚未实现。

此前版本使用 AstrBot 4.29.1 的真实工具循环和确定性提供商做隔离验证，覆盖整轮边界、多级压缩、并行追加、后台发布、截断拒绝、重启恢复、历史检索、完整工具结果、记忆队列收集、回复判断副本及 @ 绕过。使用临时数据库与无头浏览器实测了页面逐层展开、搜索、请求查看、时区、明暗主题及窄屏布局。

有效历史同步另覆盖原生保存接口、历史改删、图片替换、临时内容过滤、摘要失效、过期压缩发布冲突及并行旧快照回写；测试使用临时数据库，不修改运行中的机器人。

图片窗口另覆盖最近 N 张、同条多图、当前输入与工具图片隔离、工具循环中新增历史、流式请求、图库描述更新、摘要全部转文字，以及通过消息 ID 查到媒体 ID 后读回原始图片字节。对已有真实请求快照进行了离线投影及原生 OpenAI 适配器序列化检查，HTTP 使用本地测试传输，未请求模型服务。

token 模式覆盖预算恰好用满、最新图片超预算、连续保留最近图片、旧配置兼容、尺寸不可读时的回退、原生工具循环与流式调用。DeepSeek 图片估算与官方计算器的 2000 组尺寸输出交叉核对一致；这验证估算实现与网页规则一致，不代表已取得真实请求的逐图计费用量。

v0.5.1–v0.5.2 另覆盖旧工具结果在新轮次修订、并行工具交错、多调用配对、重复 ID、未完成及失败执行的历史呈现，以及缺失图片的文字替换、预算、媒体 ID 对齐和工具图片保存时的原记录匹配。对一份真实失败请求的 234 条消息做离线回放：原生 OpenAI 适配器最终 HTTP 报文修复前配对失败，修复后配对完整；使用本地测试传输，未向模型服务发送聊天内容。

尚未使用真实 QQ 或真实模型服务联调，摘要保真、真实模型的历史查回效果、费用与首字耗时均未验证。浏览器验证使用 AstrBot 原生页面服务和 SDK，父页面的认证请求由隔离宿主模拟；真实用户登录入口仍待安装后验证。

## 插件声明接口

插件实例提供同步 `lcm_context_rules()`，LCM 从已启用插件中读取声明。回调只组装本地资料，不发消息或调用生成模型。

| 字段 | 类型与含义 |
| --- | --- |
| `owner` | 非空且唯一的来源名，通常为插件名 |
| `system` | 字符串或 `event -> str` 同步函数，返回本插件常驻系统内容 |
| `temporary` | 字符串或 `event -> str` 同步函数，返回本次调用的临时内容；空字符串省略 |
| `history_tools` | 工具名到策略的映射：`keep` 保留、`turn` 仅当前轮、`attachment` 转为历史附件；用于声明及审计 |
| `history_projector` | 同步 `messages -> [(source_index, message)]` 函数，实现本插件的历史变换；声明 `turn` 或 `attachment` 时必填 |

投影输入是分离的原生消息字典列表；输出保留原顺序，每个保留或转换的消息必须对应一个严格递增的原始索引。可省略消息或更改其表示，不可重复索引或篡改原档案。插件负责同时处理自己的工具调用、结果与附加图片，保留其他工具；LCM 负责组合各插件投影、绑定来源 ID，并修复未完成的工具协议。调用过程中的本轮工具尾部不经过历史投影。默认没有声明的工具完整保留。

本轮临时块只加到提供商输入副本，运行器历史与原生保存器不接收该块。请求快照为用户保留当时实际输入。每次工具后的模型调用重新读取目录和有效历史；图库推荐在同轮缓存候选，避免重复推荐曝光。

v0.6.0 使用原生工具循环、原生历史保存与隔离数据库核对临时提示、工具生命周期、发图转换、完整来源压缩、并行更新和工具协议。v0.6.1 的隔离验证覆盖时间转换、原生 SQLite 历史保存、临时片段过滤、并行更新和判断输入，未调用真实模型或 QQ。

v0.6.2 新增验证原生工具列表、并行群聊隔离、权限、停用、重载清理，以及说明修改后请求快照与预算的一致性。全量回归仍有四项在修改前版本同样失败：两项旧时间格式断言、一项旧判断统计字段断言及一项缺少上下文对象的测试夹具；不将其计为本轮验证通过。

v0.6.3 新增输入版本、逐条来源对应、重复修订查回、占用冲突与事务回滚，以及修订图片归档的隔离验证。正式回复使用原生工具循环和 OpenAI 适配器，HTTP 传输在本地接收并检查，未调用真实模型或 QQ。新增 8 项验证全部通过；全量回归为 145 项通过、5 项失败。五项失败均在同一环境的修改前代码复现，涉及两项旧时间断言、旧记忆收集接口、旧判断统计字段和缺少上下文对象的夹具，未计为本轮通过。
